multiweb-manager/
├── package.json
│   ROLA: Konfiguracja projektu, zależności, skrypty (start/dev/build).
│         Główne entry: main.js (proces główny Electron).
│   UWAGI: Zależności React, Electron, electron-store, node-pty, xterm, router.
│
├── package-lock.json
│   ROLA: Lockfile npm – generowany automatycznie.
│
├── config.js
│   ROLA: Stała konfiguracja aplikacji (domyślne wartości, limity, feature flags).
│         Przykład: debugMode default, sleepTabsTimeout, historyLimit, removeBg endpoint.
│   UWAGI: Tu trzymamy rzeczy „stałe”, nie user settings.
│
├── main.js
│   ROLA: Główny proces Electron.
│         Tworzenie okna, IPC, single instance lock, global error handlers.
│   KLUCZOWE ELEMENTY:
│     - app.requestSingleInstanceLock()
│     - app.setAppUserModelId() (Windows)
│     - process.on('uncaughtException'), process.on('unhandledRejection')
│     - BrowserWindow (główne okno + Single App Mode okna)
│     - IPC: settings, profiles, tasks, notepad, history, tools, update checker
│   DEPENDS: preload.js, electron-store, node-pty, file system, config.js
│
├── preload.js
│   ROLA: Most między rendererem a procesem głównym (contextBridge).
│         Eksponuje window.electronAPI z bezpiecznymi metodami IPC.
│   ZASADY:
│     - Brak bezpośredniego dostępu do ipcRenderer poza exposeInMainWorld.
│     - Funkcje onX zwracają cleanup (do usuwania listenerów).
│   DEPENDS: electron (contextBridge, ipcRenderer)
│
├── index.html
│   ROLA: Główny dokument HTML ładowany przez Electron.
│         Zawiera #root dla Reacta, ładuje src/index.jsx.
│
├── README.md
│   ROLA: Ogólny opis projektu, skróty, podstawowa instrukcja uruchomienia.
│
├── structure.txt
│   ROLA: Ten plik – mapa struktury projektu i zależności.
│
└── DevelopersGuide.md
    ROLA: Szczegółowy przewodnik implementacyjny (architektura, feature’y, zasady).

══════════════════════════════════════════════════════════════════════

1. main.js
   - app.requestSingleInstanceLock()
   - app.on('ready') → createWindow()
   - global error handlers (uncaughtException, unhandledRejection)

2. preload.js
   - contextBridge.exposeInMainWorld("electronAPI", { ... })
   - definicje metod IPC (invoke/send/on) z cleanup

3. index.html
   - ładowany przez BrowserWindow.loadFile("index.html")
   - zawiera <div id="root"></div>

4. src/index.jsx
   - import React, createRoot
   - inicjalizacja TranslationProvider (useTranslation)
   - render <App />

5. App.jsx
   - layout: Sidebar + router
   - ładuje główne widoki (TaskPanel, WebViewTab, Notepad, ProjectManager, AggregatedTasks, Terminal, HistoryLog, Settings, Help, Tools)

6. Hooki i store’y
   - useSettings / settingsStore → ładowanie settings z IPC
   - useProfiles / profilesStore → ładowanie profili
   - useTasks / tasksStore → ładowanie zadań
   - itd.

7. Komponenty funkcjonalne
   - Sidebar, TaskPanel, WebViewTab, Notepad, ProjectManager, AggregatedTasks, Terminal, HistoryLog, Settings, Help, Tools

// KONWENCJE GLOBALNE:
// - Każdy plik ma nagłówek w ustalonym formacie.
// - Wszystkie teksty → locales + useTranslation.
// - Wszystkie ikony → icons.js (ICONS.*).
// - IPC: zawsze walidacja + try/catch + { ok, data, error }.
// - Settings: zawsze merge, nie overwrite.
// - Brak alert()/prompt() – tylko modale + toasty.
// - Event listenery: zawsze cleanup w useEffect / onX zwraca funkcję usuwającą.
